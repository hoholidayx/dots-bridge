# 通过 Bridge 与 Aion 通信

使用已授权的 `dots-bridge` MCP 连接。需要确认连接时，调用 `get_current_user()` 核对 Bridge 用户。工具不可用、鉴权失败或需要审批时，说明卡在哪一步，按当前环境的提示处理。以工具返回结果确认 Bridge 是否已保存消息。

## 接收 Aion 请求并回复

- 用户要求监听时，用 Dot 的事件任务功能订阅 `app.message.created`，频道用用户指定的值，省略时用 `default`。已有匹配的监听任务时，更新它的指令。订阅结果不明确时，先检查已有任务再决定是否重试。用户要求停止时，通过 Dot 的任务管理停止对应监听。
- 监听任务用以下规则处理每条事件。读取事件 `data` 中的 `request_id` 和 `text`，按 `text` 执行该次请求。需要补全原文、元数据或确认请求状态时，调用 `get_message(request_id)`。同一个 `request_id` 再次送达时，先核对状态，避免重复执行副作用或覆盖已保存的答复。
- 耗时任务可用 `report_progress(request_id, text, idempotency_key)` 回传有实质进展的更新。每条新进度用新键，重试同一进度时保留原键和原文。进度发出后，请求仍在等待最终回复。
- 完成后调用 `reply_to_app(request_id, text)` 回传最终结果。结论是无需处理或任务无法继续时，也用它回传原因。每个请求只存一条最终回复，重试时保留相同的 `request_id` 和原文。Webhook 已接收事件只代表送达，`reply_status` 为 `replied` 才表示最终回复已保存。
- 后来的请求明确替换同一频道、同一订阅里的旧请求时，可用 `cancel_request(request_id, superseded_by)` 关闭仍未完成的旧请求。`superseded_by` 填实际的新请求 ID。独立请求各自继续并回传各自的结果。关闭 Bridge 请求不会中止 Dot 已经开始的工作。

## 主动推送和定时任务

- 对用户已授权发送给 Aion 的通知或任务结果，调用 `send_to_app`，传入 `text`、`idempotency_key`，并按需传入 `channel` 和 JSON 对象 `metadata`。默认频道是 `default`。定时任务能访问该 MCP 工具时可直接调用，无需应用先发请求或创建事件订阅。
- 每次逻辑推送使用唯一且可重现的键。同一次定时运行重试时，复用原键以及原来的文本、频道和元数据。新的一次定时运行用新键，可由任务标识和原定触发时间组成。遇到幂等冲突时核对本次内容和原推送，避免换键重发同一条消息。
- 定时任务写明要做的工作、触发时间和时区、何时需要发送结果，以及 Aion 的目标频道。任务只在用户授权的范围内发消息。带 `request_id` 的应用请求走上面的回复流程。

## 文本和附件

进度、回复和主动推送的 `text` 都是纯文本，每条最多 64,000 字符。当前 Bridge 的 R2 上传和附件引用接口仍待实现。需要交付图片或其他文件时，可在用户授权的范围内发送已经可访问的文件链接。只有本地文件或聊天内图片时，说明文件尚未通过 Bridge 交付。文件字节和 Base64 不适合作为消息文本。
